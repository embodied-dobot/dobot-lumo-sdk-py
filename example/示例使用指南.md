# 示例快速验证

在 `dobot-sdk-py` 目录里执行下面的命令。脚本通过 `example/common.py` 自己找到上一级的 `dobot` 包，不用另设 `PYTHONPATH`。

需要 Python 3.12。扩展按 3.12 编译，3.10 和 3.14 加载不了。

```bash
python3.12 --version
```

机器人上如果 `python3 --version` 已经是 3.12，把下文的 `python3.12` 写成 `python3` 即可。

先分清两条通道：

| 通道 | 验证什么 | 不通时 |
|---|---|---|
| RPC | TCP `51234`，查状态机、切模式、设速度 | `GetFsmId 失败 connect` 或 `no_response` |
| DDS | 订阅状态、发布命令。不看机器人 IP，看 domain 和网卡 | `matched` 为 0，`Latest()` 没有数据 |

建议顺序：先查状态机，再订一帧状态，再看 10 秒周期。这三步机器人不会动。行走、切模式、摆臂、发下肢命令放在最后，并且周围留出空地。

## 连接参数

每个示例都有这些参数。示例自己的参数写在后面各节。

| 参数 | 作用 |
|---|---|
| `--model sr_3588` 或 `sr_thor` | 型号。默认 `sr_3588` |
| `--ip` | 只给 RPC。电脑上填机器人地址。机器人本机不要填 |
| `--on-robot` | 程序跑在机器人本机。RPC 连 `127.0.0.1` |
| `--nic` | 只给 DDS。填**正在跑脚本的这台机器**上的网卡名。一块网卡时可以不写 |
| `--domain` | DDS domain，默认 `0` |
| `--timeout-ms` | RPC 超时，默认 `3000` |

网卡名用 `ip -br link` 看。机器人上的运控按 `eth0` 做 DDS 发现；本机接口不是 `eth0` 时换成看到的名字。电脑上填接机器人的那块，不要填 Docker 的虚拟网卡。

| 场景 | 连接参数 |
|---|---|
| 电脑连接 SR_3588 | `--model sr_3588 --ip 192.168.5.2 --nic eth0` |
| 电脑连接 SR_thor | `--model sr_thor --ip 172.16.20.2 --nic eth0` |
| 在 SR_3588 本机 | `--model sr_3588 --on-robot --nic eth0` |
| 在 SR_thor 本机 | `--model sr_thor --on-robot --nic eth0` |

下文用「电脑连接 SR_3588」做样例。换成 Thor，或改到机器人本机，只替换上表这一段，示例自己的参数不变。电脑上不要加 `--on-robot`。本机上不要再写 `--ip`。

## 1. 查状态机：RPC 是否通

`motion_demo.py` 不带动作参数时只查询，机器人不会动。成功时打印编号和短名称，`0` 也是合法编号。

```bash
python3.12 example/motion_demo.py --model sr_3588 --ip 192.168.5.2
```

成功类似：

```text
fsm_id=300 stand
```

打印状态机列表：

```bash
python3.12 example/motion_demo.py --model sr_3588 --ip 192.168.5.2 --list
```

在 Thor 本机上：

```bash
python3.12 example/motion_demo.py --model sr_thor --on-robot
```

`connect` 或 `no_response`：先 `ping` 机器人，再确认 `51234` 通。本机运行时确认加了 `--on-robot` 且没有填写 `--ip`。

## 2. 订一帧状态：DDS 是否通

`dds_echo.py` 订阅下肢和上肢状态，默认等 5 秒，只打印，不发命令。

```bash
python3.12 example/dds_echo.py --model sr_3588 --ip 192.168.5.2 --nic eth0
```

成功时 `matched lower=` 和 `upper=` 大于 0，并打印下肢前 4 个关节角。等更久可以加 `--seconds 10`。

`没有收到状态` 或 `matched` 为 0：RPC 已经通也要查这块。核对 `--nic` 和 `--domain`。防火墙要放行这块网卡上的 UDP 7400–7500。只放行 TCP 时，第 1 步能成功，这一步没有数据。

## 3. 看 10 秒周期

`state_gap.py` 订阅下肢、上肢、主节点和骨盆 IMU。每秒打印这一秒的帧数和间隔，超过 5 ms 会立刻打出前后时间戳。结束时打印全程汇总。终端输出同时写入当前目录的 `state_gap_日期时间.log`。机器人不会动。

```bash
python3.12 example/state_gap.py --model sr_3588 --ip 192.168.5.2 --nic eth0 --duration 10
```

在 Thor 本机上：

```bash
python3.12 example/state_gap.py --model sr_thor --on-robot --nic eth0 --duration 10
```

成功时四路计数往上涨，最后有 `======== 汇总 ========`。`matched` 大于 0。不写 `--duration` 会一直运行，Ctrl+C 后打印汇总；再按一次 Ctrl+C 立刻结束。

`msg` 是消息里时间戳的前后差，`recv` 是 Python 回调被调用时的本地时间前后差。`recv` 比 `msg` 大，是回调交到 Python 的耗时，不表示运控丢帧。

## 4. 急停话题

`dds_event.py` 订阅急停，收到一帧就打印 `stop1` 和 `stop2`。默认等 5 秒。

```bash
python3.12 example/dds_event.py --model sr_3588 --ip 192.168.5.2 --nic eth0 --seconds 15
```

运行后按下或松开急停。成功时打印 `estop stop1=... stop2=...`。

时间内没有变化会打印 `matched=...，N 秒内没有收到急停` 并返回 1。`matched` 大于 0 说明订阅已经对上，只是这段时间没有新帧。`matched` 为 0 按第 2 步查网卡。

## 5. 一条尚未封装的 RPC

查状态机和切模式用 `motion_demo.py`，不要用这个脚本。`rpc_call.py` 只给还没有语义接口的方法，例如重新加载技能、下发按键映射、按文件名执行技能。`--method` 必填。`--params` 是 JSON 对象，默认 `{}`。

```bash
python3.12 example/rpc_call.py --model sr_3588 --ip 192.168.5.2 --method ReloadArmSkillsData
python3.12 example/rpc_call.py --model sr_3588 --ip 192.168.5.2 --method ExecuteAction --params '{"file_path":"skill.csv"}'
```

成功时 `error=ok`，并打印 `result`。这些调用会改机器人上的技能数据或开始动作，不是连通性测试。连通性用第 1 步。

## 6. 会让机器人动的示例

下面每条都会改变机器人状态。先做完第 1 步和第 2 步，确认人和障碍物都在动作范围外。

### 来回走

`walk_demo.py` 先切到拟人行走，向前走一段，再以同样速度向后走，重复若干次，最后发零速度停住。不加 `--run` 不会动。

`--vx` 向前速度，单位 m/s，默认 `0.2`。`--seconds` 每一段的秒数，默认 `2`。`--laps` 来回次数，默认 `1`。

先用短距离：

```bash
python3.12 example/walk_demo.py --model sr_3588 --ip 192.168.5.2 --run --vx 0.2 --seconds 2 --laps 1
```

在 Thor 本机上：

```bash
python3.12 example/walk_demo.py --model sr_thor --on-robot --run --vx 0.2 --seconds 2 --laps 1
```

成功时依次打印「已切换到拟人行走」、每一段方向，最后「已停止」。Ctrl+C 会再发一次零速度。失败时打印 `SetRobotMode` 或 `SetVelocity` 和错误名。

### 切模式、预设动作、舞蹈

`motion_demo.py` 的 `--mode`、`--action`、`--dance`、`--fsm-id` 只能指定一个。成功时先打印这次调用的返回码 `0`，再打印切换后的 `fsm_id`。

```bash
python3.12 example/motion_demo.py --model sr_3588 --ip 192.168.5.2 --mode stand
python3.12 example/motion_demo.py --model sr_3588 --ip 192.168.5.2 --mode walk
python3.12 example/motion_demo.py --model sr_3588 --ip 192.168.5.2 --action lie
python3.12 example/motion_demo.py --model sr_3588 --ip 192.168.5.2 --dance 350
```

`--mode`：`zero` 零力矩，`damp` 阻尼，`debug` 底层调试，`ready` 预备站立，`stand` 站立，`walk` 拟人行走。

`--action`：`enter-box` 入箱，`lie` 躺下，`prone` 趴下，`exit-box` 出箱，`stand-supine` 仰姿起身，`stand-prone` 俯姿起身。躺下、趴下、入箱结束后会进入阻尼。出箱和两种起身结束后会先进入行走，大约 2 秒后再进入站立。

`--dance` 的编号在 350–400。已有舞蹈用 `--list` 看。

### 上肢摆臂（仅 SR_3588）

`upper_arm_swing.py` 只适用于 SR_3588。关节序号和限位不能用在 Thor 上，写成 `--model sr_thor` 会直接退出。

它持续写 `rt/upper/cmd`。双臂第二个关节先向外让出 10°，再以这个角度为内侧起点来回摆。腰、头和其余关节保持启动时读到的角度。必须加 `--move`。机器人需要已经处于会执行上肢命令的使能状态。Ctrl+C 后先回到启动时的贴身角度；再按一次立刻结束。

```bash
python3.12 example/upper_arm_swing.py --model sr_3588 --ip 192.168.5.2 --nic eth0 --move
```

在 SR_3588 本机上：

```bash
python3.12 example/upper_arm_swing.py --model sr_3588 --on-robot --nic eth0 --move
```

可选参数：`--amplitude` 在 10° 之外再向外的幅度，弧度，最大 π/2，默认 π/2。`--period` 一个来回的秒数，2 到 30，默认 2。`--hz` 发送频率，20 到 1000，默认 1000。`--kp` 最大 40，默认 10。`--kd` 最大 5，默认 1。

5 秒内收不到 `rt/upper/state` 时不会发送命令。

### 发一帧下肢命令

`dds_publish_cmd.py` 向 `rt/lower/cmd` 发一帧全 0。这是通信匹配测试，不是安全的零位姿。不加 `--send` 不会发送。日常验证不要从这一步开始。

```bash
python3.12 example/dds_publish_cmd.py --model sr_3588 --ip 192.168.5.2 --nic eth0 --send
```

`write=True` 只表示本机 DDS 接受了这一帧。`matched` 大于 0 表示当时有订阅者。
